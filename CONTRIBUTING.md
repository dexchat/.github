# Contributing

Here are some best practices if you want to contribute to this project.
Please note that this is a personal project that I maintain in my free time. I will do my best to review contributions and ship new features within a reasonable time.

## Quick guide

### I'd like to contribute
Feel free to pick any open issue and start working on it. If you need help or guidance, leave a comment on the issue.
If you want to start contributing to the project, beginner-friendly issues are tagged with the ["contributor friendly"](https://github.com/dexchat/dex/issues?q=sort%3Aupdated-desc%20is%3Aissue%20state%3Aopen%20label%3A%22contributor%20friendly%22) label.

### New features and suggestions
If you have a new idea, please [open a discussion](https://github.com/dexchat/dex/discussions/new?category=feature-requests-and-ideas) before opening a pull request.
The idea is to agree on what will be implemented so everyone can discuss the change and provide feedback.
Discussions are also a good place to find new features to implement. Once a proposal has been discussed, you can [open a Feature Request](https://github.com/dexchat/dex/issues/new?template=feature.yml).

### I have a bug!
If you couldn't find a similar issue, feel free to [open a bug report](https://github.com/dexchat/dex/issues/new?template=bug.yml).

### I just have a question
In this case, you can open a [Q&A discussion](https://github.com/dexchat/dex/discussions/new?category=q-a) or join the [`#dexchat`](https://web.libera.chat/#dexchat) IRC channel on libera.

## Best practices

### Pull Requests Implement an Issue

Pull requests for non-trivial changes should address an existing issue. Small documentation fixes and typo corrections may be submitted directly.

- For new features, start with a Discussion so we can agree on the scope and proposed behavior. Once the proposal is accepted, open a feature request and link it to the Discussion.
- For bug fixes, link the corresponding bug report in the pull request.


> [!NOTE]
>
> **Pull requests are NOT the place to discuss the feature itself.** That should
> be done in Discussions. They are the place to discuss the code being
> implemented, though.
